# ADR-002: Chrome Extension 기술 스택 선정

> Date: 2026-03-19

## 상황 (Context)
Tistory 블로그 에디터에 마크다운 WYSIWYG 편집 기능을 제공하는 Chrome Extension을 개발하기 위해 기술 스택을 결정해야 한다.

## 선택지 (Options)

### Extension Framework
1. **WXT (Vite 기반)** — Manifest V3 자동 생성, HMR 지원, TypeScript 기본 지원. 러닝 커브가 낮고 DX가 우수 / 비교적 신생 프레임워크
2. **CRXJS (Vite 기반)** — Vite 플러그인 방식, HMR 지원 / 유지보수 불안정, 업데이트 느림
3. **수동 구성 (Webpack/Vite)** — 완전한 제어 가능 / 보일러플레이트 코드가 많고, MV3 설정 복잡

### WYSIWYG Markdown Editor
1. **TipTap v2** — ProseMirror 기반, 풍부한 확장 생태계, 마크다운 입력 룰 내장 (`#` → H1, `**` → Bold 등). 커뮤니티/문서 성숙 / 번들 ~200KB
2. **Milkdown** — ProseMirror 기반, 마크다운 퍼스트 설계. 경량 / 커뮤니티 규모 작음, 생태계 제한적
3. **BlockNote** — TipTap 기반, Notion 스타일 블록 에디터 즉시 제공 / 무거운 번들, 커스텀 제한적
4. **CodeMirror + 프리뷰** — 코드 에디터 + 별도 프리뷰 패널 / WYSIWYG가 아닌 분할 뷰 방식

### UI Framework
1. **Vanilla (No framework)** — 최소 번들, 의존성 없음 / UI 복잡해지면 관리 어려움
2. **React/Vue** — 컴포넌트 기반 개발 / 번들 크기 증가, Content Script에서 오버헤드

## 결정 (Decision)
- **Extension Framework**: WXT — DX가 가장 우수하고 MV3 지원이 안정적
- **Editor**: TipTap v2 — 마크다운 WYSIWYG에 가장 적합한 확장 생태계와 성숙한 문서
- **Language**: TypeScript — 타입 안전성, WXT 기본 지원
- **UI**: Vanilla — Content Script 번들 최소화, 프레임워크 오버헤드 제거

## 결과 (Result)
- WXT의 HMR 덕분에 Content Script 개발 시 빠른 피드백 루프 확보
- TipTap 확장을 통해 마크다운 입력 룰, HTML 직렬화 등을 플러그인으로 조합 가능
- Vanilla 선택으로 번들 크기를 최소화하되, 향후 UI 복잡도가 높아지면 경량 프레임워크(Preact 등) 도입 검토 필요
