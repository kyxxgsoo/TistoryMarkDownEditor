# ADR-003: Tistory 에디터 주입 및 TinyMCE 동기화 전략

> Date: 2026-03-19

## 상황 (Context)
Tistory 글쓰기 페이지의 기존 TinyMCE 에디터를 TipTap WYSIWYG 마크다운 에디터로 대체하되, Tistory의 발행 플로우(TinyMCE → 서버 저장)를 깨뜨리지 않고 콘텐츠를 동기화해야 한다.

## 선택지 (Options)
1. **TinyMCE를 `display:none`으로 숨기고 TipTap 에디터 주입** — 간단하지만 TinyMCE가 렌더링되지 않아 API 호출이 실패할 수 있음
2. **TinyMCE를 오프스크린(position:absolute, left:-9999px)으로 숨기고 TipTap 에디터 주입** — TinyMCE가 DOM에 렌더링된 상태를 유지하여 API가 정상 동작
3. **TinyMCE 위에 TipTap을 z-index로 오버레이** — 레이아웃 충돌 가능성, 클릭 이벤트 관리 복잡

### 동기화 방식
1. **Content Script에서 직접 `window.tinymce` 호출** — Chrome Extension의 격리된 월드 정책으로 접근 불가
2. **인라인 `<script>` 태그 주입** — CSP(Content Security Policy)에 의해 차단됨
3. **별도 MAIN world Content Script + `window.postMessage` 통신** — CSP 우회, 격리된 월드 간 비동기 통신 가능
4. **`CustomEvent.detail` 사용** — 격리된 월드 간 detail 객체가 전달되지 않음 (structured clone 제한)

## 결정 (Decision)
- **에디터 숨김**: 선택지 2 (오프스크린). `display:none`은 TinyMCE iframe이 비활성화되어 `setContent()`/`save()` 호출 실패.
- **동기화**: 선택지 3 (MAIN world script + postMessage).
  - `entrypoints/sync-bridge.content.ts`를 `world: 'MAIN'`으로 설정하여 TinyMCE API에 접근
  - Content Script → `window.postMessage()` → MAIN world에서 `tinymce.setContent()` + `save()` 호출
  - 디바운스(2초)로 주기적 동기화 + 발행/저장 버튼 `mousedown` 시 즉시 동기화 (postMessage 비동기 처리 시간 확보)

## 결과 (Result)
- TipTap에서 작성한 콘텐츠가 TinyMCE를 경유하여 Tistory 발행 API로 정상 전달됨
- Tistory의 카테고리, 태그 등 기존 메타 기능은 영향 없이 동작
- `editor.save()` 호출이 필수 — `setContent()`만으로는 Tistory가 textarea에서 읽는 값이 갱신되지 않음
- postMessage 기반 비동기 통신이므로, 발행 시점의 동기화 타이밍을 mousedown 이벤트로 보장
